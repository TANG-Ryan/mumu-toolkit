# 安装与迁移

## 1. 准备目标环境

完整解压本资料包到可写目录，运行 `START.cmd` 校验。MuMu 官方 Windows 安装器位于 `materials/windows`，版本与来源见 `metadata/assets.json`。先创建独立实例，确认 Android 版本、ABI、网络及空闲空间，再逐项安装。

当前 bszip 修复只在 MuMu Android 15、x86_64、KernelSU 3.2.5 环境完成刷入与重启检查。其他设备需重新核对。管理器 APK 的安装不能代替内核 Root、Zygisk 或 LSPosed 的实际加载。

## 2. 安装普通应用

用 MuMu 自带“安装 APK”选择 `materials/apps` 内文件，或使用 `START.cmd` 的 APK 安装助手。安装助手显示在线设备，要求明确选择目标；读取 Android API、ABI、已有版本与签名后，才执行一次 `adb install -r`。不会自动卸载、强制降级、猜端口或切换 Root。

已有更高版本、签名不同、设备状态不明确或 APK 签名读取失败时，助手会停止。保留错误及原数据，用独立实例测试或按下一节迁移。Android ARM64 应用在 x86_64 模拟器运行依赖引擎兼容层；声明 ABI 支持仍需实际启动验证。

## 3. LocationSpoofer 网络修复与迁移

包内默认使用 `LocationSpoofer_2.6.13_network_fix.apk`。原版在移动约 20 米后的环境刷新中，可能把缺省 Wi-Fi 与基站模拟重设为开启；修复将这两个缺省值改为关闭。用户明确开启的设置仍会生效，因此须保持“伪造 Wi-Fi 数据”“模拟基站数据”关闭。

首次安装可直接使用修复版。已有原版时，由于签名不同，应先通过 MuMu 支持的方式完整备份实例，再备份当前应用的数据和模块配置。确认备份可用后再更换应用并恢复。不能为解决签名错误直接卸载丢弃数据。

高级迁移应保留当前应用的 `files`、`shared_prefs`、`databases`、`no_backup`、外部文件及当前 LSPosed 作用域。新安装 UID 可能变化，恢复文件须使用新 UID 与正确 SELinux 标签；LSPosed 的模块 APK 路径必须对应新安装路径。只恢复该模块的设置，不能覆盖整份数据库或其他应用授权。

持久网络开关位于应用的 `shared_prefs/app_settings.xml`；运行镜像位于应用 `files/locationspoofer_config.json` 与 `/data/local/tmp/locationspoofer_config.json`。关闭应用中的两个开关后重启应用，检查运行镜像的 `mock_wifi=false`、`mock_cell=false`，再确认 Root 授权、LSPosed 启用与目标作用域。KernelSU 授权须匹配新 UID。

用临时路线跨过多次环境刷新点，确认两个开关持续关闭、乐跑页面可联网。测试后停止临时模拟。地图学校区域与默认位置是另一项设置；本包不预置个人学校坐标或路线，不创建、提交校园跑记录。

## 4. bszip 离线修复

在已经具备合适 Root 环境的独立实例中，使用管理器安装 `materials/modules/bszip-v2.00-offline-fix.zip`，按屏幕提示完成后重启。

修复内置已缓存安装脚本，避免安装入口依赖原云端接口；子模块出错会返回失败。x86_64 下跳过没有对应本机库的 ARM64 专用 Oh My Keymint，保留原内嵌素材。它不提供真实硬件 TEE/KeyMint 能力。

原方案会处理已有模块并改变环境设置，已有定制实例应先导出备份。不要把所有模块重复安装；本包不另行附带 ARM64 KPM、PathMask 或 HMA UID Fake 等不匹配的内核模块。不要另行重复安装已由本 ZIP 提供的依赖管理器。

实际验收应检查安装返回结果、重启完成、适用模块启用及 Zygisk/LSPosed 等运行状态。安装和模块加载成功不等于所有应用业务或硬件认证通过。

## 5. 微信与其他应用检查

逐个打开应用确认稳定启动、地图显示和正常联网。微信 8.0.80 在本机 Android 15 中曾出现 `MediaCodec_loop` / `__cfi_slowpath` 原生崩溃；停用注入模块或切换 DirectX 仍出现。请以 `metadata/validation.json` 记录的实测结果为准。

如存在相同崩溃，保留当前实例，使用独立干净实例进行对照；需要其他 Android 引擎时另建实例。不得直接卸载已有微信或在原实例回退引擎。一次启动成功不足以覆盖先前约几十秒后崩溃的情形。

## 6. 校验与故障处理

文件损坏或缺失：重新完整传输、解压并校验。签名不符或版本回退：保留原应用与数据，停止覆盖。联网失败：记录准确页面和时间，核对两个网络模拟开关，再对照实际请求错误。不能只凭系统 Wi-Fi 图标判断目标应用联网成功。

安装助手只检查已知目标与安装前条件，不运行 Root/ZIP/内核安装、账号登录、路线或校园活动。每项结果须分别记录“未测试”“通过”或实际失败，不把其他实例的旧验证写成本机通过。
